## 0. 병행 구조 — 3트랙이 아니라 2트랙

- **트랙 A(PV)** = 데이터·크론(백엔드) / **트랙 B(DS)** = 토큰·컴포넌트·화면(프론트). 파일 교차면이 거의 없어 두 CC 세션 병렬이 성립한다. 병행 push 규약(pull --rebase·Rule 번호 origin 확인·STATUS 갱신) 공통.
- **H7 2차·B7 잔여는 DS로 흡수** — 별도 트랙으로 계속 가면 같은 화면을 3중 수정하게 된다. CC는 착수 시 STATUS의 H7/B7 잔여 목록을 이 문서와 대사하고, 충돌 항목은 중단·보고.
- **`/apt/[id]` 상세는 이 트랙 범위 밖** — 업그레이드 1층 "라이프사이클 단일 페이지"와 한 몸으로 별도 설계한다(두 번 일하지 않기). 상세에서 이 트랙이 하는 일은 DS-2 컴포넌트를 준비해 두는 것까지. (단일 예외: 마스터 §3 **B8 퀵픽스** — 하단 CTA 2버튼·댓글·공유 소커밋, CC 세션 B의 1호 커밋으로 DS-1보다 먼저 처리.)
- 우선순위 충돌 시 **PV 중단점 A가 DS-2보다 우선** — 업그레이드 전체가 PV 위에 선다. 3트랙(PV+DS+업그레이드 설계서) 동시 착수 금지.
- **롤백**: 태그 `pre-ds-20260829`. 화면 단위 커밋이므로 revert 단위도 화면.

## 1. 문제 정의 — 왜 '리뉴얼'이 아니라 '시스템'인가

홈은 8/25~8/26 이틀 사이 H1→H2→H4로 세 번 재지시됐고 이후 H5·H6·H7까지 이어졌다. 원인은 취향 변덕이 아니라 **한 번 정한 결정이 화면들로 전파되는 시스템이 없어서**다. 실측 부채: hex 하드코딩 1,214 · rgba 869 · 인라인 fontSize 3,064 · letterSpacing 164 · 컴포넌트 98개 평면 산재 · globals.css 토큰 282개는 있으나 **계층이 없다**. 이 트랙의 목표는 화면 재도색이 아니라 **리뉴얼 루프의 종결**: 한 번 정하면 전 화면이 따라오고, 다음 취향 변경은 토큰 몇 줄로 끝나는 상태.

## 2. 디자인 방향 — 새 발명이 아니라 확정 자산의 화면 확장

카더라는 이미 아이덴티티가 확정돼 있다. DS는 그것을 화면까지 밀어붙인다.

- **시그니처(단 하나의 대담함)**: 브랜드 네이비 그라디언트(158deg `#0B2A6B→#123A8F 52%→#2563EB`) + **골드 `#FFC53D` 한 줄 원칙**. OG·카드에서 확정된 이 언어가 화면의 히어로·강조 모멘트를 담당한다. 나머지는 조용하게 — 대담함은 한 곳에만 쓴다.
- **고정값**: 라이트 단일 모드 · Pretendard 단일 + TY1 굵기 사다리(400 본문 / 500 라벨 / 600 제목 / 700 희소 수치, 800+ 화면 금지) · 작은 글씨 음수 자간 금지 · 대비 4.5:1 하한(#85 합성 대비로 실측) · 터치 44px+ · 입력 16px · 브레이크포인트 H5 4종 · clamp 타이포.
- **"뽀짝"의 조작적 정의(감이 아니라 수치)**: 라운드 스케일 1벌(예: 8/12/16px 3단) · 여백 리듬 1벌(4의 배수 사다리) · 그림자 2단 이하 · 마이크로 인터랙션은 절제(hover/press 상태 전이만, 장식 모션 금지, `prefers-reduced-motion` 존중) · 빈 상태·에러는 다음 행동을 안내하는 문장(사과·모호 금지).
- **"컴팩트"의 조작적 정의**: 행 42px 체계(H6 확정)를 표준으로 — 카드 104px 대비 같은 자리에 3배. 목록은 무이미지 압축 행 + 상단 큐레이션(V3 구조 유지).
- **카피 규칙**: 능동태 · 흐름 전체에서 같은 동작은 같은 이름 · "부울경" 화면 카피 금지(H5) 유지 · 라벨은 시스템 용어가 아니라 사용자 언어.

## 4. 커밋 계획

### DS-1: 파운데이션
- 토큰 3계층 재편 — primitive(색·치수 원값) → semantic(의미: text-primary, surface, accent-gold…) → component(배지·칩·행 전용). **기존 282개를 재분류가 원칙, 신설은 최소.** @layer 체계(H5 도입분)를 확장해 특이성 충돌(.section vs 요소 선택자 상쇄)을 구조로 차단.
- 죽은 다크 폴백 247건·하드코딩 부채는 **여기서 전수 치환하지 않는다**(S4-3 전역 타이포 사고 교훈) — DS-3 화면 전환 시 그 화면 것만 동반 회수.

> **B7-6(간격 체계) 흡수** — 마스터 부록 C-2. 검증 발동 트리거:
> 값 무변경 재분류로 끝나면 `tsc`·`build`·`smoke` 로 충분.
> **간격 「값」이 실제로 바뀌는 커밋**에서만 6페이지 × 5폭 절차 발동.

### DS-2: 컴포넌트 표준 8종 + `/design` 프리뷰
- 표준 8종: ①행/카드 — **B7-1 공용 2줄 행을 표준 1호로 승격** ②배지·칩(대비 사고 다발 지점 — 토큰만 허용, hex 금지) ③SectionHeader ④CTA 2종(리드폼 틴트 색면 / 회원 흰 카드+카카오 노랑, 인접 배치 금지 — S7-3 확정 유지) + **하단 고정 2버튼 바(B8 패턴: 50/50 동일 높이)를 CTA 표준에 포함** ⑤폼 필드 ⑥**검증 뱃지(verified/estimated/conflicting)** — PV 트랙 D6과 연동, 정확성을 눈에 보이는 가치로 ⑦관측 카드 ⑧빈 상태·스켈레톤.
- `/design` 내부 프리뷰 라우트 1장(noindex + 어드민 게이트) — 컴포넌트 실물·뽀짝 A/B를 실화면으로 확인하는 자리. sitemap 제외 확인.

**[중단점 C]** `/design` 프리뷰 Node 리뷰 — 뽀짝 스케일 택1 포함. 통과 전 DS-3 금지.

### DS-3: 화면 적용 — 리스크 오름차순, 홈은 마지막
1. **/stock (⑤)** — "축소 위젯" 방향이 이미 확정돼 있고 트래픽이 낮아 첫 실험장으로 최적. 부동산 80% 원칙에 맞게 존재감 축소 + DS 스킨.
2. **/blog 목록** — 지역 셀렉 재사용 구조 유지, 스킨 교체.
3. **/apt 목록** — V3 큐레이션 하이브리드 구조 유지, 표준 행·카드로 교체.
4. **홈** — 검색 퍼스트 구조(확정) 유지, 마지막에 시스템이 성숙한 뒤 스킨. 가장 자주 뒤집힌 화면을 맨 뒤에 두는 것이 루프 종결의 핵심.
- 각 화면 커밋에 그 화면의 인라인 하드코딩(폴백·hex·fontSize) **동반 회수**를 포함 — 별도 전수 작업을 만들지 않는다.

> **H7-5·H7-6 흡수** — 마스터 부록 C-3. `scripts/smoke.ts` owner 가 이미 `DS-3` 로 재배정돼 있다.

> **게이미피케이션 정리는 별도 커밋으로 분리**(policy·SEO 성격 — 커밋 메시지에 명기).
