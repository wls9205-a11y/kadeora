## 1. ⛔ 이번 층의 «가장 큰 발견» — 이 사이트의 sticky 는 전부 죽어 있었다

점프바를 6칩으로 바꾸고 **높이가 그대로인지 재려다** 발견했다.
스크롤 2,400px 지점에서 `.kd-jumpbar` 의 `top` 이 **-1,920** 이었다 — 화면 밖이다.
`position: sticky; top: 45` 인데도 그렇다.

원인은 «조상 넷» 이었다. 하나를 고칠 때마다 다음 것이 드러났다:

| # | 요소 | 무엇이 | 왜 죽는가 |
|---|---|---|---|
| ① | `<main id="main-content">` | `overflow-x: hidden`(인라인) | main 이 **스크롤 컨테이너**가 된다 |
| ② | `html, body` | `overflow-x: hidden` | 스크롤 상자가 문서 루트에서 body 로 옮겨 가 기준이 어긋난다 |
| ③ | `article`(≤479.98px) | `overflow-x: hidden` | 모바일에서만 살아 있던 같은 병 |
| ④ | `.kd-detail-rail` | 부모가 `align-items: start` | 상자가 **773px 에서 끝난다**. sticky 는 상자 안에서만 붙는다 |

→ ①②③ 은 **`clip`** 으로 바꿨다. 가로를 «똑같이 잘라내면서» 스크롤 상자를 만들지 않는다.
→ ④ 는 `align-self: stretch`. 배경·테두리 없는 상자라 시각 변화는 없다.

> ⚠️ **U-1a 에서 내가 「고쳤다」고 보고한 레일 정지선(118 → 103)은 «죽은 값» 이었다.**
> 그때 나는 토큰 값만 쟀고 «붙는지» 는 재지 않았다. 이번에 대상을 직접 재서 드러났다.
> — 「숫자를 고치기 전에 자를 고친다」의 다음 단계: **자가 맞아도 대상이 죽어 있을 수 있다.**

⚠️ Safari 16 미만은 `clip` 을 몰라 `visible` 로 떨어진다(자르지 않음).
   ds-6x6 이 6폭 × 3모드 × 6페이지에서 넘침 0 을 상시 확인하므로 지금 방어 대상은 없다.

| 클릭 0인 현장 | 277곳 |

## 그래서 무엇이 문제인가
캐시는 «누가 열어 줘야» 따뜻해진다. 그런데 **시간당 1회 이상 눌리는 현장이 하나도 없다** —
만료 주기(1시간)보다 방문이 드물다는 뜻이고, 그러면 **유료 클릭의 상당수가 만료 창에 떨어진다.**
즉 지금 구조에서는 「가끔 느린 페이지」가 아니라 **「광고비를 낸 사람이 주로 만나는 화면」** 이다.

실측된 최악은 **504(60초 초과)** 다 — 그 클릭은 랜딩을 보지도 못하고 과금만 된다.

⚠️ 반대로 읽지 말 것: **클릭 수가 적다는 것이 문제의 크기를 줄이지 않는다.**
   106회 중 몇 건이 504 였는지는 아직 모른다 — 그것부터 세는 것이 다음 정지점의 첫 걸음이다.

### ⛔ 신고 내용 중 «실측과 다른» 것 하나
「패널이 헤더 위를 덮으면서 입력이 잘리거나 가려진다」 — **겹침은 0이다.** 패널이 입력을
덮은 적이 없다. 입력창은 **화면 «위» 로 나가 있었다**(y −44 ~ −66). 가려진 게 아니라 없었다.
⚠️ 이 구분이 중요하다. 「겹침」으로 읽고 z-index 나 패널 위치를 고쳤으면 **증상 좌표만 밀어
   맞추는** 수리가 됐을 것이고, 원인은 그대로 남았다.

### ⚠️ 그리고 «가장 나쁜 칸» 은 포커스 열이다
**여섯 폭 전부에서 포커스는 입력창에 정상으로 갔다.** 즉 「열렸는가 · 포커스가 갔는가」로
재는 어떤 자도 이 결함을 **통과시킨다.** 사용자는 보이지 않는 칸에 타이핑하고 있었다.

## 2. 원인 — 하나다. `<header>` 의 `backdrop-filter`

```
fixed 기준상자 원인: header → backdrop-filter: blur(16px)     ← 6폭 전부 동일
```

`backdrop-filter` 가 `none` 이 아닌 요소는 **자손 `position: fixed` 의 «기준 상자»** 가 된다
(CSS Filter Effects). 이 모달은 `<header>` 안에서 렌더되므로 `inset: 0` 이 뷰포트가 아니라
**높이 45px 짜리 헤더**를 가리켰다 — dialog rect 가 6폭 전부 `높이 44` 인 것이 그 증거다.

그 44px 상자에 `items-center` 가 걸려 패널(≈230px)이 위아래로 반씩 튀어나갔고,
**위쪽 절반에 있던 입력 줄이 화면 밖으로, 아래쪽 절반의 「인기 검색어」 칩만 남았다.**

> ⚠️ **E 층의 「`overflow-x: hidden` 이 sticky 를 죽인다」와 같은 형태다.**
> 장식·방어 목적의 CSS 한 줄이 위치 지정 기능을 조용히 먹는다. 두 번째 사례이므로
> STATUS 공리 §3(「방어 CSS 는 방어만 하지 않는다」)에 실례로 묶어 기록했다.

### 왜 지금까지 안 잡혔나 — 「자가 맞아도 대상이 죽어 있을 수 있다」의 다른 얼굴
`ds-6x6`(넘침) · `smoke`(금칙어·콘솔) · `touch-spacing`(히트) 어느 자도 **모달을 열지 않는다.**
닫힌 화면만 재는 자에게 이 결함은 존재하지 않았다.

## 3. 고친 것 — 좌표를 밀지 않고 «기준 상자 밖» 으로 내보냈다

| 한 일 | 왜 |
|---|---|
| `createPortal(…, document.body)` | 원인이 「기준 상자가 헤더」인 것이다. 헤더 밖으로 나가면 `fixed` 가 다시 뷰포트를 본다 — **폭마다 다른 보정값이 필요 없어진다** |
| `z-index: 9999` | portal 로 나오면 헤더(z 100)와 같은 루트 쌓임 맥락이다. 50 이면 헤더가 오버레이를 덮는다. 9999 는 기존 오버레이 층(Navigation 더보기 시트)과 같은 값 |
| 오버레이 = `flex-start` + `padding-top: var(--kd-overlay-top)` | 입력이 «항상 위», 패널이 «항상 아래». 값은 토큰 하나로만 산다 |
| 입력 줄 `flexShrink: 0` · 결과 패널 `flex: 1 1 auto; minHeight: 0` | 결과가 길어져도 입력 줄이 먼저 자리를 갖는다. 이번 결함이 정확히 「패널이 커져 입력이 밀린」 모양이었다 |
| ESC 를 «열려 있는 인스턴스» 가 소유 | 전에는 ⌘K 리스너 안에 얹혀 있어, `hotkey={false}` 인 모바일 아이콘은 **입력창에 포커스가 있을 때만** 닫혔다. 칩으로 포커스가 옮겨 가면 ESC 가 죽었다 |
| 닫은 뒤 포커스 복원 | 열기 «직전» 활성 요소를 기억해 돌려준다. 없으면 포커스가 `<body>` 로 떨어진다 |
| 모달 안 칩·지우기·전체결과에 `.touch-target` | 히트 44 (§1-5 이원 체계 ② — 시각 크기는 그대로) |

`--kd-overlay-top` 은 6폭 × 5모드 **전부 56px** — 모드 오버라이드도 걸지 않았다(token-baseline 30행).

### ⛔ 하지 «않은» 것

  (globals.css 실측 주석). **고치려다 같은 병을 새로 만드는 자리다.**
- **패널·칩 색을 토큰으로 재작성.** 모달 내부가 `bg-white`·`text-gray-900` 같은 고정색이다.

# ⛔⛔ 결함 2호 (등재만 — 손대지 않았다) · 스크롤하면 **헤더 전체가 죽는다**

## 실측
| 요소 | position | z-index | rect(스크롤 900) |
|---|---|---|---|
| `StickyTalkBanner` (`a.fixed`, 노란 공유방 띠) | **fixed** top 0 | **110** | 0..52 |
| `<header>` | sticky top 0 | **100** | 0..45 |

`elementFromPoint(돋보기 중심)` = **`a[부동산 정보 공유방 … 새 창으로 열기]`** — 자기 자신 아님.

- 스크롤 0 에서는 헤더가 52..97(띠 아래)이라 정상이다. **스크롤하는 순간** 헤더가 top 0 으로
  붙으면서 z 110 짜리 띠 밑으로 들어간다.
- 즉 로고 · 검색 바 · 돋보기 · 내비 · 더보기 · 아바타가 **전부 안 보이고, 누르면 카톡방이 열린다.**
  안 보이는 것보다 **오클릭이 더 나쁘다.**
- 띠가 렌더되는 모든 라우트가 대상이다(`/`, `/apt`, `/blog` 목록 …).
  현장 상세·블로그 상세·complex 상세는 띠를 안 그려서 해당 없다.

## ⚠️ 이것이 H5-1 의 의도를 무효로 만든다
Navigation 주석: 「히어로가 스크롤로 숨으니 모바일 홈에서 스크롤 뒤 검색 진입점이 0개가 된다
→ 그래서 헤더 돋보기를 마운트한다」. **그 돋보기가 정확히 스크롤 뒤에 죽는다.**
대비책이 대비해야 할 그 상태에서 같이 죽어 있었다.

## 손대지 않은 이유
고치는 길은 「헤더 `top: 0` → `top: 52`(띠 높이)」쪽이 유력하나, 그 값은 **파일을 건너**
`--rail-top: 103`(헤더 45 + 점프바 42 + 16)·점프바 `top: 45` 와 한 줄로 이어져 있다.
띠는 상세에서 렌더되지 않으므로 **「띠가 있을 때만 다른 헤더 오프셋」** 이라는 조건부 값이 생긴다 —
그 조건을 토큰 하나로 둘지, 띠 자체를 헤더 «안» 으로 옮길지는 판정이 필요하다.
⛔ 임의로 고르지 않는다. **지시를 주면 즉시 집행한다.**

# 🔧 결함 2호 — 띠와 헤더를 «겹치지 말고 쌓는다» (2026-08-30 · 집행 완료)

> 판정: 「띠(52) 아래 헤더가 오도록 하되, 하드코딩 연쇄를 손으로 따라 밀지 마라.
> 크롬 스택을 토큰으로 승격하고 하위 sticky 기준선은 전부 그 합에서 파생.
> 띠 없는 라우트는 `--kd-banner-h:0` 으로 조건이 값에 흡수된다 — 라우트별 CSS 분기 금지.」

## 1. 수리 «전» 실측 (프로덕션)

| 요소 | position | z-index | rect(스크롤 900) |
|---|---|---|---|
| `StickyTalkBanner` 노란 띠 | **fixed** top 0 | **110** | 0..52 |
| `<header>` | sticky top **0** | **100** | 0..45 |

`elementFromPoint(돋보기 중심)` = **`a[부동산 정보 공유방 … 새 창으로 열기]`**.
스크롤 0 에서는 헤더가 52..97(띠 아래 흐름 위치)이라 멀쩡하고, **스크롤하는 순간**
헤더가 top 0 에 붙으면서 z110 짜리 띠 밑으로 들어간다. 로고·검색·돋보기·내비·아바타가
전부 안 보이고, **그 자리를 누르면 카톡방이 열린다.** 안 보이는 것보다 오클릭이 나쁘다.

## 2. 스택을 토큰으로 (tokens.css)

```
--kd-banner-h      노란 공유방 띠. 띠가 없는 라우트는 0
--kd-header-h      헤더 높이 45 (내부 44 + 아래 테두리 1)
--kd-header-top    = var(--kd-banner-h)                     헤더가 «멈추는» 자리
--kd-header-bottom = calc(--kd-header-top + --kd-header-h)   그 아래 것들의 기준선
--kd-jumpbar-h     42
--kd-overlay-top   = max(--sp-lg, calc(--kd-banner-h + --sp-xs))
```

### ⛔ 라우트별 CSS 분기 «0»
「띠가 있는가」는 분기가 아니라 **값**이다. `StickyTalkBanner` 가 렌더될 때만
자기 출력 안에 `<style>:root{--kd-banner-h:52px}</style>` 를 싣고, 안 그리는 라우트에서는
tokens.css 의 `:root` 기본 **0** 이 그대로 산다. 판정(`hidden`)이 그 컴포넌트 한 곳뿐이므로
**값도 한 벌**이다.

> ⚠️ 첫판에는 `useEffect` 로 `<html>` 에 썼다. token-snapshot 이 **같은 페이지에서
> `0px` 과 `52px` 을 섞어 찍었다** — 읽는 시점이 효과보다 빠르면 0 이다.
> 깜빡이는 게이트는 없는 게이트보다 나쁘다. SSR `<style>` 로 바꿔 **첫 페인트부터 확정**이다.
> `@layer` 밖이라 `:root`(@layer tokens) 기본값을 «항상» 이긴다 — 순서에 기대지 않는다.
