# P0-B — 표면별 적재 이력 실측 (2026-08-31 · 세션 B)

> 로그인 프로브가 막힌 제약에서 「어느 표면이 언제부터 죽었나」를 **DB 시계열로** 확정한다.
> ⚠️ 이번 교훈대로 **각 표면의 실제 적재 테이블을 코드에서 먼저 확정한 뒤** 셌다
> (DS_RULES §4-6 · `docs/telemetry-map.md`).

---

## 0. 한 줄 판정

**사용자 작성 표면은 「최근까지 살아 있다」가 아니라 「2026-04-19 주부터 전부 0」이다.**
그런데도 살아 보였던 이유는 **시드 크론이 같은 테이블에 계속 쓰고 있었기 때문**이다.
그리고 **현장 댓글은 역사상 한 번도 성공한 적이 없다** — 코드 결함이었다(§4).

## 3. 「8/22 정지」의 정체 — 표면이 아니라 **시드 크론 등록 해제**

- `seed-posts` 는 8/22 까지 **매시간(24회/일)** 돌며 하루 ~75건을 만들었다.
  8/22 에 13회 돌고 **완전 정지**, 이후 실행 0.
- 원인은 실패가 아니다 — **`33ef3821`(2026-08-22 11:32) 「크론 19건 정리」가
  vercel.json 에서 `seed-posts` 등록을 뺐다.** 마지막 실행 8/22 12:00 은 그 배포 직후 정각이다.
- 이어서 **`b96c7ff6`(2026-08-27) 「A1 시드 격리」** 가 `seed-posts`·`seed-comments`·`seed-chat`
  호출을 8곳에서 제거했다. 그 커밋은 같은 결론을 이미 기록해 뒀다 —
  「`mv_community_feed_hot` 을 시드 제외로 다시 만들자 행이 200 → 0 이 됐다.
  최근 30일 커뮤니티 인기 글 200건이 **전부** 시드 글이었다.」
  **이 문서는 그 발견을 UGC 전체로 넓혀 확인한 것이다.**
- ⚠️ **정정**: `daily-seed-activity` 는 `cron_logs` 에 기록이 **아예 없다** — 스케줄된 적이 없다.
  그 라우트가 `blog_comments` 에 **존재하지 않는 열 `user_id`** 로 insert 하는 결함은
  「매일 조용히 실패」가 아니라 **한 번도 실행된 적 없는 잠재 결함**이다. 켤 때 먼저 고칠 것.

## 4. ⛔ 현장 댓글은 **역사상 100% 실패**하고 있었다 (신규 P0)

`apt_comments` 실사용자 행 **0건**. 유일한 1행은 다른 경로가 넣은 것이다. 원인은 둘이 겹쳤다:

1. **`house_type` 은 NOT NULL 이고 DB 기본값이 없다.**
   상세 페이지가 마운트하는 `AptCommentSection.submit()` 은 그 열을 **안 보냈다** →
   모든 insert 가 제약 위반으로 실패.
2. **그 실패를 아무도 보지 않았다.** `await sb.from('apt_comments').insert({...})` 의
   반환값을 통째로 버렸다 → 입력창은 비워지고 스피너는 멈추고 목록만 그대로.
   **사용자에게는 「등록을 눌렀는데 아무 일도 없다」로 보인다.**

⚠️ V4-D P0-A 의 하단 바 침묵 반환과 **같은 병의 다른 표면**이다.
   그때 세운 원칙(「폼이 없으면 그 폼으로 보내는 버튼도 없다」 · 침묵 금지)이
   이 화면에는 적용되지 않은 채 남아 있었다.

**수리**(같은 커밋): `house_type` 적재 + `error` 확인 + 실패 시 문장 노출
(`role="alert"` · `aria-invalid` · ⛔ 실패 시 입력 보존).

## 5. 남긴 안건 (의도적으로 안 고친 것)

1. **`apt_comments` 쓰기 경로가 두 벌이다.** `AptCommentSection`(클라 직접)과
   `/api/apt/comments`(인증·레이트리밋·포인트 지급·검증)가 공존하고, 컬럼 어휘도 다르다
   (`author_name` vs `profiles` 조인). 클라 경로는 레이트리밋도 포인트도 없다.
   → 단일화는 표시 이름 출처까지 건드리므로 **별 판정**으로 올린다.
   (`SiteFloatingActions` 주석이 이 이원화를 이미 경고하고 있었다.)
2. **`daily-seed-activity` 의 `blog_comments.user_id` 오적재** — 켜기 전에 고칠 것.
3. **피드 존폐**는 Node 판정 안건이다. 이 문서는 데이터만 댄다.

## 6. 이 실측이 답하지 못하는 것

- 커뮤니티가 **깨져서** 0 인지 **아무도 안 써서** 0 인지는 이 표가 단독으로 못 가른다.
  다만 5월 이후 신규 가입 **33명**의 행동은 이렇다:
  글 0 · 댓글 0 · 좋아요 0 · 북마크 0 · **현장 관심등록 3**.
  → 신규 유입은 **apt·리드 쪽으로만** 움직인다. 커뮤니티는 «비어 있다» 쪽에 무게가 실린다.
- 단, **현장 댓글만은 「안 쓴 것」이 아니다** — §4 대로 **쓸 수가 없었다**.
  그 표면의 0 은 수요의 증거가 아니다.
