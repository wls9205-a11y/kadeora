# 수치 게이트 v2 — 의미 축 매칭 (처방 2단 설계 1p · ABG 증분 5 · 2026-09-15)

## 문제
허용 목록은 «값의 집합» 하나다. 본문 금액이 목록의 «어떤» 값과 허용폭 안이면 통과한다.
그래서 **실거래 집계 값이 분양가 문장을 허가**할 수 있다(112444: 「2억원대 예상 분양가」 ← 블록 「실거래 최저 2억 1,000만원」).
처방 1단(추정 표현 사전, 집행)은 «추정 문형» 을 끊었지만, 추정어 없이 「분양가는 2억 1,000만원」이라고 쓰면 여전히 실거래 값으로 통과한다.

## 설계
### ① 주입 블록 카테고리화 (허용 목록을 칸으로 가른다)
| 카테고리 | 원천(issue-context 조립 줄) | 예 |
|---|---|---|
| `trade` 실거래 집계 | 「같은 시군구 아파트 실거래(…)」 줄 | 중위·최저·최고 |
| `sale_price` 공고 분양가 | 「분양가: …」 줄(비합성·공고 유래만) | price_min~max |
| `schedule` 일정 | 예상 분양 시기·청약 접수·당첨자 발표·입주 예정 줄 | ym·연도 |
| `policy` 제도 상수 | 제도 상수 블록 | LTV %, 한도 억, 가점 점수 |
| `source` 원문 발췌 | 기사 본문 | 기사 속 금액 |
`Allow` → `Record<Category, {amount[], ym[], pct[], year[]}>`. `buildAllow` 는 줄 접두어로 칸을 정한다(조립 줄 형식이 곧 스키마 — 줄 형식 변경 시 테스트가 깨지게 골든 픽스처).

### ② 본문 토큰의 술어 문맥 → 요구 카테고리
토큰 앞뒤 창(같은 문장, ±40자)의 술어어 사전으로 요구 칸을 정한다.
| 술어어(예) | 요구 칸 |
|---|---|
| 분양가·공급가·평당 분양·계약금·중도금 | `sale_price` (원문 발췌에 분양가로 명시된 값 포함 → `source` 중 분양가 문맥만) |
| 실거래·시세·거래가·매매가·중위 | `trade` ∪ `source` |
| LTV·DSR·한도·취득세·가점·전매 | `policy` |
| 분양·청약·입주·당첨 + 시기 | `schedule` |
| 사전 미적중 | 전체 칸(현행 동작) — 섀도 로그로 사전 증보 |
표·목록 행은 **헤더·첫 열 라벨**을 문맥으로 쓴다(「분양가(억원)」 열의 셀은 `sale_price`).

### ③ 판정
토큰은 «요구 칸» 의 값하고만 허용폭 비교. 다른 칸 값과만 맞으면 `unverified` + 사유 `category_mismatch:{요구}←{맞은 칸}`.
허용폭(±)은 표기 반올림용 그대로. 처방 1단(추정 표현)은 칸 판정보다 먼저.

## 롤아웃
1. 섀도 1주: 부동산 글에서 v1 판정은 그대로 차단 기준, v2 판정은 `raw_data.gate_v2` 기록만 — v1 통과·v2 실패 목록을 표본 판독.
2. 오탐률 표본 10 기준 통과 시 v2 를 차단 기준으로 승격(세션 A 판정). 사전 미적중 비율 ≤10% 가 승격 조건.
3. issue-context 공용층이라 생성·편집·retry-stale 동시 적용(이중 생산자 없음).

## 불변
허용 목록 소스 확대 없음(칸만 가른다) · 게이트 완화 없음(v2 는 v1 ∩) · 표기 반올림 허용폭 유지.
