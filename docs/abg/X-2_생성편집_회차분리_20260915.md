# X-2 — issue-draft 생성/편집 회차 분리 (1p · 2026-09-15 · 집행 79147611)

## 문제
EX-A2 감산 편집 1회가 생성 회차 안에 있어 부동산 건당 최악 ~240s(생성 60–120 + 편집 60–100 + 마무리 ~20). Vercel 300s 한도에서 **회전당 1건**, 초과 시 타임아웃 → 잠금만 남고 판정 소실(EX-B 실측 4회차 연속). hub 70 일정이 이 병목에 갇힌다.

## 설계
| | 생성 회차 | 편집 회차 |
|---|---|---|
| 호출 | vercel.json `*/10` `/api/cron/issue-draft` | pg_cron jobid 180 `5-59/10` `?mode=edit` |
| 기록 | cron_logs `issue-draft` | cron_logs `issue-draft-edit` |
| 대상 | `is_processed=false` (기존 LB-4 정렬) | `publish_decision='edit_pending'` 오래된 순 6 |
| 잠금 | `is_processed` CAS | `edit_pending→editing` CAS |
| 동시성 | 3줄 · 새 건 시작 컷오프 130s | 3줄 · 컷오프 150s |
| 게이트 통과 | `finalizeArticle`(시각화·SEO·적재·이미지·발행) | 같은 `finalizeArticle` |
| 게이트 실패 | 본문만 실패 → `edit_pending` + `raw_data.edit_pending{article,first_unverified}` / 제목 실패 → 즉시 `number_unverified` | 감산 편집 1회 → 같은 게이트 재판정 → 통과 `passed_after_edit` / 실패 `number_unverified`+`blocked_draft` |
| 죽은 잠금 회수 | 판정 없는 잠금 6h·8분 → 1회 회수, 재발 `timeout` | `editing` 6h·8분 → `edit_pending` |

- 문맥·허용 목록은 `src/lib/content/issue-context.ts` 한 곳(생성·편집·retry-stale 공용) — 편집 회차는 문맥을 **다시 읽어** 같은 허용 목록을 만든다(`edit_pending`·`blocked_draft` 는 허용 소스에서 제외 — 자기 허가 방지).
- 발행 상한 회차당 2(시작 시점 판정)는 유지.

## 처리량 산식 (게이트 §3-②: 회전당 ≥3)
- 생성 회차: 3줄 × (컷오프 130s 전 시작 가능 건) — 통과 건 ~80–140s, 쿼터 보류는 수 초 → 3줄이 각 1–2건 = **3–6건/회전**.
- 편집 회차: 3줄 × 1건(편집 ~100s + 마무리 ~20s) = **3건/회전**.
- 실측 축: `cron_logs` 두 이름의 `processed` 와 `stopped_reason`, 타임아웃 여부(`status='running'` 잔존).
