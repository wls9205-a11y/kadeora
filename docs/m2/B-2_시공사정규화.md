# M2 B-2 — 시공사 정규화

2026-08-25 · 마이그레이션 `m2_b2_builder_normalized`

## 무엇이 문제였나

`/apt/builder/[name]` 이 `.eq('builder', name)` — **원문 완전일치**로 조회했다.
그래서 두 가지로 갈라졌다.

| 원인 | 규모 |
|---|---|
| ② **컨소시엄 행이 어느 허브에도 안 잡힘** | `builder` 에 쉼표가 있는 행 **265개** |
| ① 표기 변형이 허브를 가름 | `(주)` 120행 · `주식회사` 30행 + 별칭 |

M2 는 ①만 지목했지만 실측하면 **②가 더 크다.** `"GS건설, SK에코플랜트"` 는
GS건설 허브에도 SK에코플랜트 허브에도 나오지 않았다.

## 무엇을 만들었나

```
normalize_builder(text) → text[]        IMMUTABLE 함수. 규칙이 사는 유일한 자리
apt_sites.builder_normalized text[]     원본 builder 는 그대로 보존
trg_apt_sites_builder_normalized        BEFORE INSERT/UPDATE OF builder 동기화
idx_apt_sites_builder_normalized        GIN — contains 조회용
```

**GENERATED 컬럼 대신 트리거를 쓴 이유**: B-3 진행 중 별칭 사전이 계속 바뀔 예정인데,
GENERATED 는 함수를 고칠 때마다 컬럼을 떼었다 붙여야 한다.
트리거면 사전을 고치고 백필만 다시 돌리면 된다.

```sql
-- 사전을 고친 뒤 반드시 이걸 다시 돌린다
UPDATE apt_sites
SET builder_normalized = normalize_builder(builder)
WHERE builder_normalized IS DISTINCT FROM normalize_builder(builder);
```

## 정규화 규칙

1. 구분자 `,` `/` `·` 로 분리 → 컨소시엄이 배열 원소가 된다
2. `(주)` `（주）` `㈜` `주식회사` 제거
3. 꼬리표 제거 — `등` · `외 N사` · `컨소시엄` · `건설부문`
4. 공백 접기(collapse) + 트림
5. 별칭 사전 적용

### 공백과 `&` 를 구분자로 쓰지 않은 이유

- 공백으로 자르면 `한화 건설부문` · `계룡건설산업` 이 쪼개진다
- 공백을 **지워도** 안 된다 — `삼성물산 대림산업 HDC현대산업개발` 이 한 덩어리로 뭉개진다
- `&` 로 자르면 `DLE&C` 가 `DLE` + `C` 로 찢어진다

그래서 공백으로만 구분된 다중 시공사 1건(`삼성물산 대림산업 HDC현대산업개발`)은
한 원소로 남는다. **알려진 한계다.**

### 일부러 합치지 않은 것

**별개 법인이다. 합치면 서로 다른 회사의 현장이 한 허브에 섞인다.**

```
DL건설 / 대림건설 / 대림종합건설   ≠ DL이앤씨   (DL건설은 구 삼호·고려개발)
대우건설 / 대우산업개발 / 대우조선해양건설
호반건설 / 호반산업
우미건설 / 우미개발
대방건설 / 대방산업개발
라인건설 / 라인산업
한양 / 한양건설 / 비에스한양        판단 보류 — 확신이 낮다
한라공영                            ≠ HL디앤아이한라
```

`디엘` · `대림` 같은 단독 약칭도 어느 법인인지 확정할 수 없어 그대로 뒀다.

## 코드 쪽 변경

| 파일 | 변경 |
|---|---|
| `apt/builder/[name]/page.tsx` | `.eq('builder')` → `.contains('builder_normalized', [name])` |
| `sitemap/[id]/route.ts` | 허브 URL 열거를 정규화 배열 집계로 |
| `api/cron/indexnow-mass/route.ts` | 같음 |
| `apt/[id]/page.tsx` | 시공사 허브 링크를 정규화 이름으로. 컨소시엄이면 링크 여러 개 |
| `types/database.ts` | `builder_normalized` 필드 추가 (Row/Insert/Update) |

사이트맵·IndexNow 를 같이 고친 이유: 허브가 정규화 이름으로만 열리는데
사이트맵이 원문을 실으면 `/apt/builder/GS건설,%20SK에코플랜트` 같은 URL 을
색인 요청하게 되고 그 페이지는 `notFound()` 다.

상세 페이지 링크도 같은 이유다 — 지금까지 컨소시엄 현장의 시공사 링크는
빈 허브로 나가고 있었다.

## 손대지 않은 것

`lib/apt-fetcher.ts` 의 `/apt` 목록 필터는 여전히 원문 `builder` 로 거른다.
필터 칩 목록도 같은 원문에서 뽑으므로 그 화면 안에서는 앞뒤가 맞는다.
허브 URL 공간과는 별개 표면이라 이번 범위에서 뺐다 — 바꾸려면 칩·필터·쿼리를
한 번에 옮겨야 한다.

## 트리거 실행 순서 결함

`apt_sites` 에 이미 `trg_normalize_builder`(`normalize_builder_name`)가 있었고,
그 함수는 `NEW.builder` 를 **제자리에서 다시 쓴다**(사명 통일·법인 접미 제거).
B-2 때 이걸 못 보고 트리거를 하나 더 얹었다.

PostgreSQL 은 BEFORE ROW 트리거를 **이름 알파벳순**으로 실행한다.
`trg_apt_sites_builder_normalized`(내 것) 가 `trg_normalize_builder`(기존) 보다
먼저 돌아, 원본 builder 로 배열을 만든 뒤 기존 트리거가 builder 를 갈아 치웠다.

```
builder = '디엘건설' 입력
  전:  builder='DL이앤씨'  builder_normalized=['디엘건설']   ← 어긋남
  후:  builder='DL이앤씨'  builder_normalized=['DL이앤씨']   ← 일치
```

마이그레이션 `m3_fix_builder_normalized_trigger_order` — 트리거 이름을
`trg_sync_builder_normalized` 로 바꿔 기존 트리거 뒤에 돌게 했다. 함수는 그대로다.
저장된 데이터의 불일치는 0건이었다(백필이 기존 트리거 적용 이후였다).

**앞으로 트리거를 추가할 때 이름의 알파벳 순서가 곧 실행 순서라는 점을 잊지 말 것.**

## 사전 충돌 — 판단 대기

기존 `normalize_builder_name()` 이 **`디엘건설` → `DL이앤씨`** 로 합친다.
이 문서 「일부러 합치지 않은 것」에 적은 판단과 정면으로 어긋난다.
지금은 기존 트리거가 `builder` 자체를 바꾸므로 기존 사전이 이긴다.
`두산에너빌리티 → 두산건설` 도 같은 성격이다.

둘 중 하나는 틀렸다. 기존 트리거가 앞서 있어 의도가 있을 수 있으므로
**건드리지 않고 보고만 했다** (`docs/m2/T2-2_is_active_이력_보고.md`).
