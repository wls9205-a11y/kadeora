## B-4 비활성/활성 뒤집기 — **전제 재검토 필요**

M2 는 이렇게 적었다.

```
부산 감만1 재개발      cs90  비활성  |  감만1 재개발   cs48 활성
부산 범천1-1구역 재개발 cs100 비활성  |  범천1-1 재개발 cs48 활성
```

**실측은 정반대다.** 두 건 모두 고득점 쪽이 이미 **ON**, 저득점 쪽이 **OFF** 다.
M2 가 예시로 든 문제는 이미 해소돼 있다.

### 숫자

| 조건 | 행수 |
|---|---|
| 비활성 + `content_score >= 80` | **219** |
| 그중 더 낮은 점수의 활성 쌍둥이를 가진 것 | **46** |

M2 의 30건은 어느 쪽과도 맞지 않는다.

### 46건은 정비사업 중복이 아니라 슬러그 규칙 교체 잔재로 보인다

| 근거 | 값 |

| ON 쪽 슬러그에 `--` 공백 흔적 | **0** / 46 |

### `is_active` 를 누가 언제 왜 껐는지 — 이력이 없다

`apt_site_events` 는 `event_type='stage_change'` 429행(2026-08-23~24)뿐이고
`is_active` 변경 이력은 남지 않는다. 비활성 219행 중 `stage_source` 가 채워진 건 1건이다.
**B-3/B-4 를 진행하려면 먼저 `is_active` 변경을 이벤트로 남기는 장치가 필요하다.**
