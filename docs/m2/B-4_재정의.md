# M2 B-4 — 재정의 결과

2026-08-25 · 조사 + 승인 후 실행 완료.
**`apt_sites` 의 `is_active` 는 한 행도 바뀌지 않았다** — 병합표 등록만 했다.
판정 기준은 **RULES#118** 으로 승격했다.

## 결론 먼저

**조치 대상 0건.** 219건 전부가 중복 정리로 은퇴한 쪽이다. 하나도 되살리면 안 된다.

M2 의 B-4 는 "좋은 페이지가 꺼지고 얇은 중복본이 살아 있다"를 전제로 뒤집기를
지시했는데, 그 전제가 성립하는 행이 없다.

## 주신 기준으로 분류

`비활성 AND content_score >= 80` = **219건** (M2 의 30건이 아니다).

| 분류 | 건수 | 판정 |
|---|---|---|
| A. 같은 사업 쌍 · 활성쪽이 동점 이상 | **167** | 이미 정상. 조치 불필요 |
| B. 같은 사업 쌍 · 비활성쪽이 고득점 | **46** | 병합 구 슬러그. 유지 |
| C. 이름 기준으로 쌍이 안 잡힘 | **6** | 실은 병합 구 슬러그. 유지 |

C가 "단독"으로 보인 것은 내 이름 정규화 키가 생존자 이름과 달랐던 탓이다.
정확한 조인 키는 이름이 아니라 `apt_site_merges` 다.

## B·C 가 되살릴 대상이 아닌 이유 — 실측

`apt_site_merges` 로 다시 세면 이렇게 갈린다.

| | 건수 |
|---|---|
| 비활성 cs80+ | 219 |
| 그중 `apt_site_merges.dead_slug` 로 등재 | **210** |
| 병합표에 없음 | **9** |

B그룹 46건은 `MERGED_SLUGS` 에 **46/46 전부 구 슬러그(리다이렉트 키)** 로 등재돼 있다.
생존자로 등재된 건 0건, 미등재 0건. C그룹 6건도 전부 같다.

`src/middleware.ts` 가 `survivorSlug()` 로 301 을 건다. 즉 **이 46건을 켜면
middleware 가 이미 다른 곳으로 넘기고 있는 URL 이 되살아난다.**

그리고 `src/lib/apt/merged-slugs.ts` 헤더가 이 건을 직접 다룬 기록을 남겨 두었다.

```
⚠️ 생존자 선정에 slug 품질 기준이 빠져 23쌍이 거꾸로 잡혀 있었다
   (`dmc-sk-view-아이파크포레` → `---아이파크포레`). DB 담당이 방향을 뒤집었고,
   이 파일은 그 수정본 기준이다. 깨진 생존자 0건을 확인하고 생성했다.
```

**`content_score` 로 생존자를 고르는 것이 바로 그 23쌍을 거꾸로 만든 기준이다.**
이미 한 번 고친 것을 되돌리는 셈이라, 이 그룹에는 점수 축을 쓰면 안 된다.
높은 점수는 은퇴한 행에 남은 잔여값이지 페이지 품질이 아니다.

```
꺼짐  ---아이파크포레                          cs100
살음  dmc-sk-view-아이파크포레                  cs94   ← middleware 가 여기로 301
```

## 병합표에 없는 9건 — 여기가 진짜 B-4 후보였다

전부 `updated_at` 이 **2026-04-22** 로 같다. 병합 배치(2026-08-21)보다 앞선
**4월 배치**가 끄기만 하고 `apt_site_merges` 에 등록하지 않았다.
`stage_source` 는 9건 모두 비어 있고 `stage_locked` 도 전부 false —
**사람이 아니라 배치가 껐다**는 신호다(같은 날 9건, 지역이 제각각).

그런데 짝을 붙여 보면 되살릴 대상이 아니다. **9건 모두 살아 있는 쪽이
점수도 높고 슬러그도 깨끗하다.**

## 남은 진짜 문제 — 9건이 301 되지 않는다

이 9건은 `apt_site_merges` 에 없으므로 **middleware 가 301 을 걸지 않는다.**
구 URL 로 들어오면 생존자로 넘어가지 않고 404 가 난다.
색인·블로그 내부 링크가 걸려 있으면 그대로 유실된다.

### 제안

```sql
-- 9쌍을 병합표에 등록 (사람 확인 후)
INSERT INTO apt_site_merges (dead_slug, new_slug, ...) VALUES ...;
```
그 뒤 `node scripts/gen-merged-slugs.mjs` 를 다시 돌려 `merged-slugs.ts` 를 갱신한다.
`is_active` 는 **건드리지 않는다** — 이미 맞다.

## M2 검증 항목 수정 제안

```
현재:  [ ] content_score 80+ 비활성 30 → 0
```

이대로면 달성할 수 없다. 219건을 0으로 만들려면 전부 켜야 하고, 그러면 병합으로
정리한 중복 페이지가 통째로 되살아난다. 다음으로 바꾸는 걸 제안한다.

```
[ ] 비활성 cs80+ 중 apt_site_merges 에 없는 행 9 → 0 (병합표 등록으로)
[ ] merged-slugs.ts 재생성 후 9개 구 URL 이 301 로 생존자에 도달
[ ] is_active 변경 건수 0 — 이 작업은 아무것도 켜거나 끄지 않는다
```

## 남은 숙제

`apt_site_events` 에 `is_active` 변경 이력이 없다. 이번에는 `updated_at` 군집과
슬러그 모양으로 "배치가 껐다"를 추정할 수 있었지만, 다음 배치에서도 같은 추정이
가능하리라는 보장이 없다. `event_type='active_change'` 를 남기는 장치가 필요하다.
