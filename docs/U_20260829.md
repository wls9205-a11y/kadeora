# 설계서_U_20260829 — 3층 업그레이드 (라이프사이클 페이지 · 알림 구독 · 리드 단위경제)

> **문서 지위**: 마스터(최종통합지시서_20260829) §U의 실행 설계. 착수 조건이던 **중단점 A는 2026-08-29 통과**. 이 문서는 즉시 전량 실행되는 지시서가 아니라 **접합 시점이 각기 다른 3층의 대기 설계서**다 — 각 층의 착수 조건이 §4에 명시되며, 조건 성립 전 착수 금지(R-2).

---

## 0. 병행 전제

- 트랙 A(PV)는 PV-3b~PV-5 진행 중, 트랙 B(DS)는 DS-3 진행 중. **U는 세 번째 병렬 실행 트랙이 아니다** — 두 트랙이 만든 자산을 소비하는 접합 설계이며, 실행 시 해당 세션의 커밋 순서에 편입된다(3트랙 동시 착수 금지 유지).
- 공통 규율 승계: R-1~R-4 · D1~D6 · §7-1 표기 컴플라이언스 · 게이트 체계(PV 오라클·DS 5종) · docs/ 문서 동기화 · STATUS 갱신.
- **금지 재확인**: 앱 개발 · 커뮤니티 기능 · PBN/새 위성 확장 · 3층 동시 착수 · 조감도 수집 · 경쟁 앱 스크랩.

## 2. 문제 정의 — 왜 이 3층인가

P·V·DS가 완성해도 카더라는 아직 **"정확한 데이터가 잘 정리된 목록"**이다. 남는 갭 셋: ①현장 한 곳의 생애가 한 페이지에서 읽히지 않는다(정비→허가→공고→청약→입주가 흩어짐) — 체류·재방문·GEO 인용의 근거 부재 ②방문자가 "다음에 또 올 이유"가 없다 — 관측은 쌓이는데 구독 통로가 없어 재방문이 검색 재유입에만 의존 ③리드가 얼마짜리인지 모른다 — 채널이 매체 단위라 P4 자동 입찰이 눈 감고 돈을 건다. 3층은 이 순서대로 **콘텐츠 자산 → 관계 자산 → 수익 엔진**을 세운다.

## 3. 층별 설계

### U-1층: 라이프사이클 단일 페이지 (/apt/[id] 전면 리뉴얼) — 본체

동결돼 있던 상세 페이지의 유일한 개편 창구. DS 트랙이 "상세는 U-1층과 한 몸"으로 미룬 그 작업.

- **정보 구조(위→아래)**: ①헤드라인 — display_name + VerifiedBadge + expected_sale_period("2026년 9월 분양예정" — 원문 정밀도 그대로, §7-1 한정어·출처·기준일 연동) ②**생애 타임라인** — 정비 축·분양 축 이벤트를 시간순 단일 축으로(조합설립→시공사 선정→관리처분→인허가(permit)→공고→청약→입주). 각 노드에 출처 뱃지. apt_observations + apt_permits + 청약홈 레코드 통합 렌더 ③핵심 수치 카드(세대·면적·가격 — confidence 연동, conflicting은 "출처 충돌" 명시) ④**본부장 노트** — Node의 현장 코멘트(분양 실무자의 한 줄 — 경쟁 데이터 앱이 절대 못 베끼는 차별화 자산). admin 입력, D4 검수 영역, 없으면 섹션 미노출 ⑤최근 움직임(RecentObservations) ⑥주변·비교(기존 유지) ⑦CTA — ActionBar 교체(SiteActionBar 퇴역, B8 이월 1호) + 2층 구독 진입점.
- **GEO(생성형 검색 대응)**: 페이지 상단 구조화 요약 블록(현장 개요 3~4문장 — AI가 인용하기 좋은 자기완결 단락), FAQ 3~5문(JSON-LD FAQPage), 기존 JSON-LD에 이벤트·일정 확장. "카더라 확인 기준" 문구로 출처 브랜딩.
- **노출축 ① 네이버 웹문서**: 리뉴얼된 상세가 웹문서 탭에 걸리도록 — 색인 게이트(PV-3b) 통과 확인 + 제목·설명 메타 최적화 + 사이트맵 우선순위. 위성(Hostinger)에서의 자연 인용 유도는 기존 운영 범위 내(PBN 확장 금지).
- **노출축 ④ 캐러셀/피드**: /feed의 관측 카드가 현장 상세로 딥링크 — 상세 리뉴얼과 동시 점검(신규 개발 아님, 연결 확인).
- **하드코딩 회수**: DS-3 규약대로 이 화면 몫의 라운드·gap·인라인 회수 동반(650건 중 상세 몫 + 44px 클러스터 잔여).

### U-2층: 알림 구독 — "이 현장, 소식 오면 알려줘"

- **트리거(기계)**: expected_sale_period 변경 · lifecycle_stage 승격 · 신규 관측(중요 등급) · 공고 등록. 전부 기존 크론이 이미 감지하는 이벤트 — 신규 수집 없음, 배선만.
- **수집(UI)**: 1층 CTA에 "분양 소식 알림" — LeadForm 스택 재사용(inquiry_type='소식알림' 계열은 이미 실증됨: pre_notice 경로). 채널은 1차 카카오 채널 메시지·2차 문자(발송 인프라는 실행 시점 실측 후 확정 — 임의 신설 금지).
- **§7-1 준수**: 알림 문면도 한정어 규칙 동일("예상 시기가 10월로 변경되었습니다(출처: 인허가, 미확정)").
- **단위경제 연결**: 구독자 = 리드의 상위 깔때기. site_slug별 구독 수를 갭워치에 1지표 추가.

### U-3층: 리드 단위경제 — 키워드가 돈을 배우게

- **키워드 해상도(중단점 A 안건 ③의 실행)**: 3층 협의 확정분 — ①LeadForm이 광고 파라미터를 `ad_keyword` 별도 필드로 동봉(channel 오염 금지 — 555행 경고 준수) ②Apps Script 패스스루 ③fn_insert_lead·leads 수용 컬럼. LeadForm 555행 규약 존중.
- **깔때기 대시보드(admin)**: 키워드→클릭(광고비)→리드→(수동 입력) 상담/계약. 갭워치·PL 지표와 한 화면.
- **P4 접합(9/11)**: expected_sale_period 접근 + 리드 단가 실측 → 입찰 상향/키워드 자동 등록의 입력. **P4 전에 3층이 최소 1주 데이터를 쌓아야** 자동 입찰이 눈을 뜨고 시작한다 — 이것이 3층을 9/11 전에 두는 이유.

## 4. 착수 조건·순서 (동시 착수 금지)

| 층 | 착수 조건 | 실행 주체 |
|---|---|---|
| U-3층 | **즉시 가능** — 코드 접점 작음(LeadForm 필드+Apps Script+컬럼), P4(9/11) 역산 데드라인 | 세션 A(스키마·라우트) + Node(Apps Script 반영) + 채팅(검증) |
| U-1층 | DS-3의 /apt 목록 완료(행·카드 표준이 실화면 검증된 후) **AND** PV-3b 실적재 가동(타임라인에 실데이터) | 세션 B(DS-3 순서에 편입: 목록 다음·홈 전) |
| U-2층 | U-1층 배포 후(진입점이 그 페이지) | 세션 A(트리거 배선) + B(UI) |

**권고 순서: 3층 → 1층 → 2층.** (숫자 역순이 맞다 — 3층이 가장 작고 데드라인이 있으며, 1층이 본체, 2층이 1층 의존.)

## 5. 검증

- 1층: 게이트 5종 + 6폭 + 스모크 + **GEO 실측**(주요 AI 검색에 현장명 질의→카더라 인용 여부 주간 기록) + 색인 게이트.
- 2층: 구독→트리거→발송 E2E 1건 실증(테스트 구독) 후 공개.
- 3층: 테스트 리드 1건으로 ad_keyword E2E(PL-4 방식 재사용). 대시보드 수치 = DB 재현 쿼리 일치.

## 6. 성공 지표

- 1층: 상세 체류시간·재방문율 상승 추세 / GEO 인용 첫 확인 / 웹문서 탭 노출 확인.
- 2층: 구독 전환율(상세 방문→구독) · 알림 발송 후 재방문.
- 3층: **키워드별 리드 단가가 숫자로 존재** — P4 첫 자동 조정이 이 숫자를 근거로 실행되면 층 완성.
