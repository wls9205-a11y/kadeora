### AD-3 — JSON-LD 단일 경로화 (기존 컴포넌트로 codemod)

실측: 이스케이프(`<`) 완비 `src/components/seo/JsonLd.tsx` **채택 0** / `src/lib/jsonld.ts` 헬퍼 채택 2 / ld+json을 원시 `JSON.stringify`로 emit하는 파일 후보 **71** (재실측할 것). 크롤 유래 텍스트에 `</script>`가 섞이면 HTML 파손·스크립트 탈출 벡터 — "선언은 있는데 읽는 자가 없다" 이중 사례.

치환 규칙:
- 목적지는 컴포넌트 단일: `<script type="application/ld+json" dangerouslySetInnerHTML={{__html: JSON.stringify(X)}} />` → `<JsonLd data={X} />`
- 이미 문자열을 만들어 넘기는 코드는 **객체 전달로 재작성** — 스키마 값·구조 무변경(diff에 데이터 변화 0), 표현만 바뀐다(파싱 결과 deep-equal).
- lib 헬퍼 사용 2파일도 컴포넌트로 통일. `jsonld.ts`는 삭제하지 말고 "정본은 components/seo/JsonLd" 주석 1줄만.
- `'use client'` 파일에서도 컴포넌트는 동작한다(훅 없음) — 예외 없이 치환, 정말 불가한 파일은 보존+사유 보고.
- generateMetadata 안의 JSON-LD가 아니라 **본문 script 태그**가 대상이다. metadata의 other 필드는 건드리지 않는다.

게이트: `grep -rl "application/ld+json" src --include="*.tsx" | grep -v components/seo/JsonLd` → **0** / 표본 3페이지(블로그 1·apt 상세 1·홈) 로컬 렌더 소스에서 각 ld+json 블록 `JSON.parse` 성공 + `<` 존재 / 빌드+tsc.
