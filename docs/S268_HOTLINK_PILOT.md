# s268 ② 뉴스 핫링크 교체 — 파일럿 50편 (2026-09-01)

## 왜

발행된 글 3,820편에 뉴스사 이미지 핫링크 12,934행이 걸려 있다. 전부 `storage_path`가 NULL —
남의 서버 이미지를 그대로 거는 형태라 저작권과 403 깨짐이 동시에 걸린다. 유입은
`issue-draft`의 자체 이미지 검색 필터가 `daumcdn`·`tistory` 둘뿐이라 뉴스 도메인이 통과한
것이었고, 그 구멍은 `43e3c6f3`(공용 `isBlockedImageUrl` 적용)에서 닫혔다.

**hydrate로 우리 Storage에 복사하는 것은 해결이 아니라 복제라 악화다.** 자체 생성 카드로
교체하고 원본 행을 제거한다.

## 문제의 실제 크기 (2026-09-01 실측)

| 항목 | 수 |
|---|---|
| 핫링크가 걸린 발행분 | 3,820편 |
| ↳ **본문 마크다운에 URL이 박힌 글** | **127편** |
| ↳ `cover_image`가 핫링크인 글 | 949편 |
| ↳ `apt_site_id` 보유 (자체 카드 생성 가능) | 991편 |
| ↳ apt 계열 | 2,272편 |

약 3,690편은 DB 행에만 있고 본문에는 없다 — 행 교체만으로 끝난다.

| 3차 | 미발행 4,175행 (노출 없음) | 대기 |

## 대상 선정

정렬 기준을 **최근 발행순**으로 잡았다. 처음에는 조회수 상위를 쓰려 했으나
`blog_posts.view_count`가 합성값이다(총합 745,303 대 30일 실조회 2,617) — 합성값으로
우선순위를 정하면 「영향이 큰 것부터」라는 말 자체가 성립하지 않는다.

큐 투입: `blog_image_backfill_queue`에 `priority=1`, `target_image_count=3`, `status='pending'`.
`blog-generate-images`(매시 :32, `BATCH_SIZE=20`)가 3회에 걸쳐 처리한다.

## 절차 (글당)

1. **카드 생성 먼저** — 배포된 파이프라인이 `buildSelfMadeCards`로 카드를 만들어 hydrate·기록
2. 핫링크 행 삭제
3. 삭제 **전** `cover_image`가 핫링크면 새 카드 URL로 재지정
   — `trg_bpi_cover_sync`가 position 0을 따라가므로 **순서를 어기면 커버가 빈다**
4. 원본 행은 `blog_post_images_backup_s268`에 통째 보존

**실데이터 2항목 미만이라 카드가 안 생기는 글은 억지로 만들지 않는다** — 「교체 불가·보류」로
분류해 결과표에 남긴다(빈 카드 금지).

## 검증 5종

- (a) 핫링크 잔존 0
- (b) `check_publish_gate` 통과 유지 — **교체 후 3장 미달이 나와도 발행은 유지하고 목록만 보고한다.**
  게이트는 신규 발행용 자이고 기발행 소급 비공개는 하지 않는다
- (c) `cover_image` 비어 있는 글 0
- (d) 본문 `![](imgnews…)` 0
- (e) 표본 5편 실제 렌더 확인

## 롤백

백업 테이블에서 행 복원 + `cover_image` 원복. 1차는 본문을 건드리지 않으므로 순수 DB 작업이다.

## 안 하는 것
